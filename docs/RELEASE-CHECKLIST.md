# قائمة اعتماد إطلاق Barkoul.ma

هذه القائمة تميّز بين ما تم تنفيذه وما لا يزال يحتاج إلى اختبار فعلي.

## قاعدة البيانات والأمان
- [x] تدقيق جداول public وRLS والسياسات والصلاحيات الأساسية.
- [x] نقل دوال الإدارة والعمليات المميزة إلى private وإغلاق anon.
- [x] مواءمة مفاتيح cargo بين الجداول.
- [x] حاوية خاصة لوثائق السائقين وسياسات وصول المالك/الإدارة.
- [x] حماية دور المستخدم وطلبات تفعيل driver/owner.
- [x] منع عروض السائق غير المعتمد ومنع تكرار العرض المعلق.
- [x] عمليات قبول العرض وتحديث الرحلة ومشاركة الموقع محكومة من قاعدة البيانات.
- [x] كشف بيانات الاتصال للمشاركين بعد إنشاء الرحلة فقط.
- [x] إنشاء عمولات 10 MAD للمالك و20 MAD للسائق بعد التسليم، مع سجل تحصيل إداري.
- [ ] تفعيل حماية كلمات المرور المسربة؛ غير متاحة حالياً في خطة Supabase المجانية.
- [ ] تجربة استعادة نسخة احتياطية فعلية.

## الويب
- [x] تصفح الشحنات وتسجيل الحساب والدخول واستعادة كلمة المرور.
- [x] طلب تفعيل دور المستخدم.
- [x] نشر الشحنات لأصحاب البضائع المعتمدين.
- [x] تقديم العروض للسائقين المعتمدين بوثائق موثقة.
- [x] إدارة قبول/رفض العروض والرحلات وGPS.
- [x] رفع وثائق السائق ومراجعتها إدارياً.
- [x] عرض العمولات وسجل التدقيق.
- [ ] اختبارات تكامل بحسابات منفصلة owner/driver/admin على بيئة اختبار.
- [ ] اختبار الإشعارات والتزامن وانقطاع الشبكة والتحميل الكبير.
- [ ] اختبار أمن الملفات والخصوصية على جهاز فعلي.

## الدفع
- [x] دفتر عمولات داخلي وتسجيل التحصيل النقدي/الإلكتروني بعد تحقق المدير.
- [ ] لا يوجد مزود دفع إلكتروني مربوط. يجب اختيار مزود والتحقق من الرسوم والشروط وأخذ موافقة صريحة قبل ربطه أو إنشاء أي حساب مدفوع.

## التطبيقات
- [ ] توليد وبناء APK/AAB واختباره على Android.
- [ ] توليد وبناء IPA واختباره على iOS باستخدام macOS/Xcode.
- [ ] بناء مثبت Windows واختباره.
- [ ] اختبار PWA والتثبيت والعمل دون اتصال والتحديث.

## الإطلاق
- [ ] مراجعة النسخ الاحتياطي وخطة التراجع.
- [ ] اعتماد جميع نتائج الاختبار.
- [ ] موافقة صاحب المشروع على دمج PR ونشر النسخة النهائية.

لا يتم الدمج إلى main أو نشر النسخة الجديدة قبل اكتمال بوابة الاعتماد والموافقة النهائية.
