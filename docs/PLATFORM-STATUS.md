## اختبار قاعدة البيانات المتكامل

في 20 نوفمبر 2026 نُفّذ اختبار تكاملي محاكى داخل معاملة PostgreSQL ثم أُلغيت المعاملة بالكامل (ROLLBACK). استخدم حسابات اصطناعية مؤقتة، ولم تُحفظ أي حسابات أو شحنات أو وثائق أو رحلات أو عمولات اختبارية في الإنتاج.

شمل الاختبار:
- إنشاء profile تلقائي لحساب Auth جديد، وإنشاء شحنة بصلاحيات الأعمدة المسموح بها.
- منع تعديل/حذف الشحنة مباشرة ومنع تصعيد الدور.
- تسجيل وثيقة سائق مرتبطة بكائن موجود في مجلد السائق، ثم مراجعتها من المدير.
- منع مسار سياسة الحذف من حذف وثيقة موثقة، ومنع وثيقة تشير إلى ملف غير موجود أو مجلد مستخدم آخر.
- منع عرض بسعر صفر، وإنشاء عرض صحيح، وقبول العرض.
- إظهار بيانات الطرف الآخر للمشاركين فقط.
- انتقال الرحلة من agreed إلى loading ثم in_transit ثم delivered.
- إنشاء عمولتي 10 و20 درهماً، وتسجيل تحصيل نقدي وإلكتروني تجريبي.
- طلب ترقية دور وموافقة المدير، والتحقق من أن غير المدير لا يرى سجل التدقيق.
- إلغاء شحنة وإغلاق عروضها المعلقة.

نجح هذا الاختبار المحاكى، وأكد الفحص اللاحق أن كل سجلات الاختبار المؤقتة أُزيلت بالـROLLBACK. هذا لا يعادل اختبار تسجيل الدخول الفعلي أو إرسال البريد أو استخدام Storage API من المتصفح.

## قاعدة البيانات والإطلاق

- تم تطبيق migration `20261120140715` على مشروع Supabase الإنتاجي.
- حساب Auth النشط الذي كان يفتقد profile أُنشئ له profile بدور `owner` لأنه يملك شحنة موجودة؛ لا توجد ترقية تلقائية إلى admin.
- بقيت البيانات التجارية الحالية كما هي: شحنة واحدة، ولا توجد وثائق أو عروض أو رحلات أو عمولات.
- Health advisor بلا تحذيرات. بقي تحذير Leaked Password Protection لأنه غير متاح في خطة Supabase Free، وتحذيرات الفهارس غير المستخدمة معلوماتية ولا تستدعي حذفها الآن.
- الواجهة الجديدة لم تُنشر بعد. سير GitHub Pages الحالي يبني من المصدر القديم؛ يجب ضبط Settings → Pages → Source على GitHub Actions ثم تشغيل `Deploy Barkoul.ma to GitHub Pages` يدوياً.
- لا يوجد مزود دفع إلكتروني مربوط؛ التحصيل الإلكتروني الحالي هو تسجيل مرجع تحقق خارجي من المدير.
